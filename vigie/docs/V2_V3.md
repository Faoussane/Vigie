# V2 & V3 — fonctionnement

## V2 — Veille
```
Source (feed_url) ──Celery Beat (5 min)──▶ collect_due_sources
        └▶ collect_source_task ▶ VeilleItem (NEW) ▶ notifications ▶ analyze_item_task (V3)
```
- Lancer : `celery -A config worker -l info` et `celery -A config beat -l info` (Redis requis),
  ou `docker compose up`. Sans Redis : `CELERY_EAGER=True` ou `python manage.py collect_feeds`.
- Kanban : `GET /api/veille/items/?status=NEW`, déplacer avec `PATCH {"status": "TO_VERIFY"}`.
- `POST /api/veille/items/{id}/create_article/` crée un **brouillon** d'article.
- Statistiques : `GET /api/veille/stats/`. Notifications : `/api/notifications/`.
- Collections de favoris : `/api/collections/` et `POST /api/articles/{slug}/favorite/ {"collection": id}`.

## V3 — IA (assistant, jamais autonome)
- `AI_PROVIDER=local` : heuristiques sans clé. `AI_PROVIDER=gemini` + `GEMINI_API_KEY` : API Gemini
  (modèle `GEMINI_MODEL`, défaut `gemini-2.5-flash`, tier gratuit). Si un appel échoue (quota, réseau), le mode local prend le relais.
- L'analyse automatique est limitée à 10 tâches/minute par worker pour respecter les quotas gratuits.
- Résultats = propositions (`ai_data`, `suggested_category`, `importance`, `duplicate_of`) ; rien n'est publié seul.
- Endpoints : `/api/ai/{summarize,extract,classify,assist}/` (admin), `/api/ai/search/?q=` et
  `/api/ai/trends/` (public), `/api/ai/recommendations/` (connecté).
- Les tendances sont des comptages sur les données collectées.
- Sécurité : le contenu RSS est traité comme donnée non fiable (balises `<contenu>`, sorties validées).
- Mode `local` : les actions `outline`, `titles`, `rewrite`, `conclusion` de `/api/ai/assist/` renvoient 503.
